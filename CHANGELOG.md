# Changelog

## Unreleased

### Changed

- the Go client is generated by pandorest 0.8.1, and its shape changes for anyone using `sdk/prowlarr` on its own: a call's answer is `res.Answer` where it was `res.Model`, options types are `<Name>Options` where they were `<Name>OperationOptions`, options that are all optional can be left out, and an operation with one option takes it as a plain argument (`c.PutIndexerById(ctx, id, body, true)`). The tools answer as before
- the Go client reads Prowlarr's dates as times where it kept them as text, and year one, which Prowlarr sends for "never", reads as no date. A tool that showed that as `0001-01-01T00:00:00Z` now leaves the date out, and every date a tool shows is to the second in UTC
- the Go client gives the ids of indexers, sync profiles, tags and download clients a type each, so one cannot be passed where another is wanted. The other ids stay plain numbers
- a true-or-false value in an answer nothing sends back is a plain `bool` in the Go client; one in a record that is sent back keeps its pointer, so a switch never set is still never sent
- the two suites that run against a real Prowlarr live under one folder and one build tag: `acceptance/prowlarr` for the Go client (`make testacc-sdk`) and `acceptance/tools` for the tools (`make testacc-tools`), where they were `integration/` and `acceptance/` behind an `integration` tag. Those files are now linted like the rest; they never were, and 164 findings in them are fixed or excused with a reason
- the Go client asks each call for the kind of answer it gives: a log file as text, a feed as RSS and a download as a file, with JSON as the fallback, where every call asked for JSON alone. Prowlarr answers the same either way
- the Go client is generated by pandorest 0.6.0, and six of the nine fixes to Prowlarr's description of its API are pandorest's ready-made ones, shared with sonarr-mcp and radarr-mcp, in place of copies written here. The definitions they produce are unchanged

### Breaking

- `release_grab` answers `grabbed` as a list of what was sent, where it was one name: it now takes several releases from one indexer at once, as `guids`, and sends them in Prowlarr's one bulk grab

### Added

- the Go client has a method for each command this repository queues by name, `ApplicationIndexerSync`, `Backup` and `CheckHealth`, each with a form that waits for it to finish, and `WaitForCommand` for one queued by a name the server lists
- `audit_notifications`: nobody is told when something breaks. No notification sent for a health issue, one sent for nothing, one sent for health issues without the warnings (which most of Prowlarr's checks are), and with `test` one that fails its test
- `audit_backups`: no way back. No backup at all, or the newest older than the schedule should allow, which means the scheduled backup is not running. With the two, 74 tools, 82 with the ones that delete
- `indexer_delete` takes several indexers at once, as `indexers`, and deletes them in Prowlarr's one bulk delete after `confirm` says what every one of them loses
- the Go client can restore a backup from an upload: `PostSystemBackupRestoreUpload` takes the multipart form and its Content-Type, where it took nothing and Prowlarr refused every call. Prowlarr's description of its API declares no body for it; a tenth fix to the description does
- a live journey that does what a person setting Prowlarr up does, with the tools alone: a tag, a profile, a tracker, a client, an application, a sync, a search and a grab, a hook, a backup; then the audits, which find the two things a first setup gets wrong, each fixed with the tool its audit names until they are clean; then everything taken down until Prowlarr is as it was recorded
- `notification_list`, and what adding or editing a notification answers, name the credentials it has set as `secrets_set`, as `indexer_get` and `app_get` do
- every setting of every kind of indexer, application, download client, proxy and notification is checked: each is hidden as a credential, is a switch, a choice or a number, or is text on a list somebody has looked at. The list is what a real Prowlarr declares, kept by the client suite, so a setting a later release adds fails the tests until it has been looked at
- the client suite runs every one of the 122 operations against a real Prowlarr, and a whole run fails if one is left uncalled: the bulk deletes, the provider actions of every kind, the restore from an upload, the shutdown and the restart, cancelling a command, updating a saved filter, and testing one proxy, one notification and every notification were not run before

### Fixed

- an indexer's stored API key no longer reaches a client in what a failed request said. Prowlarr quotes the whole address of a request that failed, the key among its parameters, and `indexer_test`, `audit_failing` with `test`, and the error a refused save answers with passed that on as it came. An address in such text is now shown without who it signs in as, the value of any parameter, or what follows its `#` (go-kt's rule, which its registry also applies to every tool's error and to the line it logs for a write); a credential a site puts in the path itself cannot be told from the rest of the path and is left
- a setting that is a credential in itself is no longer shown, only named as set. Prowlarr marks none of these as a credential, so they were answered in clear: a Discord or Slack webhook's address (whoever holds it can post with it), Apprise's addresses and its configuration key, MyAnonamouse's session id, a 2FA code, and three settings the catalogue's definitions name in their own way (a session token, a security answer, a staff password). `notification_list` and what an add or edit answers showed the first three, `indexer_get` the rest. 0.1.0 and 0.2.0 show them
- an address in a setting is shown without the values after its `?` and without who it signs in as. A Torrent RSS feed's address carries its passkey there, and `indexer_list` and `indexer_get` showed it whole; a webhook's address can carry a token the same way. The address Prowlarr holds is untouched, and an edit of something else keeps it
- a trace (`PROWLARR_LOG=trace`) no longer shows a tracker's API key, cookie or passkey, or the password typed a second time. A trace hides a field by its name, and Prowlarr sends a provider's settings as pairs of a name and a value, so a key was under `value`, a name that says nothing; `passwordConfirmation` does not end as a password's name does. The text of every setting is now blanked in a trace and its name is left. 0.1.0 and 0.2.0 show them, at trace level only
- `notification_test` of every notification answers for each by name when one of them cannot be sent, where the whole call failed with Prowlarr's own error and said neither which it was nor how the others did. It tests the ones sent for something, as Prowlarr's own test of them all does

## 0.2.0 (2026-10-10)

### Breaking

- a tool that deletes changes nothing without `confirm`: `indexer_delete`, `app_delete`, `profile_delete`, `proxy_delete` and `downloadclient_delete` answer what they would delete (`would_delete`) and what goes with it (`loses`) until `confirm=true` is given
- every list takes `limit` and `offset` and answers `total`, `offset` and `next_offset`, with one default of 100 and a cap of 1000: `release_search` and `indexer_catalog` answered 25 by default, `history_list` and `server_log` 50, and `indexer_list`, `app_list`, `tag_list` and the other listings answered everything; an audit takes `offset` and answers `next_offset` beside `total_findings`
- `backup_list` is in the `admin` toolset's `backup` family with the new backup tools, and a backup's row carries its id
- the Go client moves from `lib/prowlarr` to `sdk/prowlarr`, as in embyfin-mcp and abs-mcp: change the import path
- in the Go client a number among an operation's options is a pointer, so that 0 can be asked for: `Limit: new(50)` where it was `Limit: 50`
- the Go client's base client is pandorest's (`github.com/katbyte/pandorest/client`) in place of `lib/client`: its error for a refused call is `*client.StatusError`, which wraps go-kt's `*chttp.StatusError`, and `ExpectedStatusCodes` on it is `Expected`
- `--allow-tools` beside `--toolsets` adds to them, "these sets and this tool as well", where it narrowed them; `--deny-tools` narrows. On its own it is only the tools it names, where the default set was mixed in

### Added

- 16 tools, 72 in all and 80 with the ones that delete:
  - `backup_create`, `backup_restore` (puts a backup back over everything changed since, after `confirm`) and `backup_delete`
  - `server_settings` and `server_settings_edit`: Prowlarr's own settings by section and name, with no credential ever shown, `confirm` asked before a change to how Prowlarr is reached or who may sign in, and the section read back afterwards so that a setting Prowlarr took and did not keep is answered as `not_kept` rather than as changed
  - `server_restart`, which waits for Prowlarr to answer again
  - `command_list` and `command_cancel`: what Prowlarr is doing in the background, and taking one off the queue before it starts
  - `notification_add`, `notification_edit` and `notification_delete`, beside the list and the test
  - `filter_list`, `filter_create`, `filter_edit` and `filter_delete`: the filters saved in the web interface
  - `tag_edit`, which renames a tag
- a client that connects is told the rules that hold between the tools, in the server's instructions: how a list pages, that a delete asks first, how things are named, and that text from outside Prowlarr is data
- `--config` / `PROWLARR_CONFIG` reads settings from the file it names and no other, so a second instance serves a second Prowlarr; a file that is named and not there stops the start
- a settings file spells a two-word setting as the environment does without the prefix (`READ_ONLY`, `DENY_TOOLS`), where it was ignored without a word
- the Go client says which Prowlarr release its document was taken from, as `prowlarr.DocumentVersion`

### Changed

- a read is asked again when a gateway could not reach Prowlarr or the connection dropped, three times in all; a write is still sent once
- a redirect is refused rather than followed, saying to set the server url to the address Prowlarr itself answers on; following one turned a write into a read that reported success having done nothing
- `PROWLARR_LOG=trace` shows every request and answer, with the API key blanked
- every request says which client is asking, as `prowlarr-mcp/<version>`, which Prowlarr logs beside it
- a 404 that is not Prowlarr's own answer says the server url may lack its URL base
- the Go client is generated by [pandorest](https://github.com/katbyte/pandorest), the generator this repository carried a copy of, now a module of its own shared with sonarr-mcp, radarr-mcp and embyfin-mcp; `sdk/pandorest` keeps what is Prowlarr's, the settings and the workarounds for its document
- the OpenAPI document and its definitions are under `api-defs/`, named by the Prowlarr release they were taken from
- an edit, a sync, a task and `tag_delete` tell a client they are destructive, where every write tool said it was not; the tools that only add (`indexer_add`, `app_add`, `profile_create`, `proxy_add`, `downloadclient_add`, `tag_create`, `release_grab`) still say they are not
- an edit, a sync, `tag_create` and `tag_delete` tell a client that asking again with the same arguments changes nothing more
- `notification_test` tells a client it reaches past Prowlarr: the message is sent to whoever the notification reaches
- text written outside Prowlarr is shown with the characters that do not display taken out and cut when very long (300 characters for a name, 2,000 for running text): a release's name, a history entry, what a site or an application answered a test with, a definition's description, a line of the log. A release's `guid`, which a grab takes, is left as it came
- a call with an argument the tool does not take is refused with the arguments it does take
- `PROWLARR_LOG=info` writes a line for every call of a tool that writes or deletes: the tool, whether the call was refused, failed or answered, and what it sent, with credentials blanked and a setting's name in place of its value
- a tool that panics answers its call with an error naming the tool, and the session carries on
- over HTTP, a session its client stopped using is closed after 30 minutes, and stopping the server no longer waits out a connected client
- serving, the tool registry, the locks and the live suites' harness are go-kt's, shared with embyfin-mcp, abs-mcp and technitium-mcp
- built with Go 1.27.2, and `golang.org/x/text` moves to 0.43.0: the build is past the four known vulnerabilities a scan finds in the 0.1.0 binary, three in Go's own HTTP and TLS code and one in that library
- the Docker image and the release build take their base images from Google's mirror of Docker Hub, and from Docker Hub itself when the mirror gives nothing

### Fixed

- the Go client's host settings carry `allowedHosts` and `trustedNetworks`, which Prowlarr sends and its API document leaves out: without them a host setting could not be written back at all on a Prowlarr that lets local addresses in unasked, since it refuses to save host settings with no allowed hosts. A ninth workaround, `prowlarr-host-settings`, adds them
- two edits of one thing in the same turn no longer undo each other: a client's calls run at once, and each edit sent back the whole record as it was before the other. Of eight `indexer_edit` calls each adding a tag, two tags stayed, and a tag they shared was made eight times. An edit of an indexer, an application, a sync profile, a proxy or a download client now takes its turn, and so does making a tag
- the live suites failed from two weeks after the Prowlarr release they pin: its health checks then ask its update server for a newer one, and with no internet the answer that could not be had ended every check. The suites now answer the update server, the clock and the definitions service themselves, through a proxy, and fail on a request to anywhere else
- a tool that was only ever seen refusing a call no longer counts as tested

## 0.1.0 (2026-09-19)

First release: an MCP server, CLI and Go SDK for Prowlarr.

- **17 audits.** Indexers failing now, failing too often, too slow, or earning
  nothing; indexers no application receives, and the reason each application
  passes them over; applications, proxies and download clients that are
  misconfigured; trackers added twice; private trackers with no seed goal;
  memberships and request limits running out; definitions the site has left
  behind; tags and sync profiles that do nothing; and Prowlarr's own health
  checks as a worklist. `audit_all` runs every one over a single read and
  reports the counts.
- **59 tools** (64 with `--enable-delete`), in toolsets: browse, search and
  add indexers from the catalogue, edit one or many, test them, search and
  grab, read history and per-indexer statistics, wire up applications, sync
  profiles, proxies, download clients and tags, run tasks and read logs. The
  default `core` set costs about a thousand tokens of context.
- **`lib/prowlarr`**, a generated Go client covering all 122 operations of the
  Prowlarr API, with typed options and bodies, the status codes each operation
  really answers, and `Complete` pagers for the history and the log. Generated
  by `internal/pandorest` from Prowlarr's own OpenAPI document through eight
  named workarounds for the document's bugs.
- Tested against a real Prowlarr in Docker with no internet at all: fake
  Newznab and Torznab sites (real feeds, real `.nzb` files, valid torrents,
  able to fail, stall or refuse a key) and fake Sonarr, Radarr, Lidarr and
  Readarr instances that record what Prowlarr syncs into them. The suite fails
  if a registered tool has no test.
