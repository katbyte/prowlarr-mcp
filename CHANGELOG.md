# Changelog

## 0.4.0 (2026-10-14)

Only the Go client changes; the tools answer as before.

### Breaking

- in the Go client, applications, proxies and notifications each have their own id type too, so the ids on a tag can only be matched with the right kind of thing

### Added

- the Go client lists every operation it has, with its method, path and group, in `prowlarr.Operations`

## 0.3.0 (2026-10-12)

Credentials that 0.1.0 and 0.2.0 could show are now hidden; upgrading is recommended.

### Breaking

- `release_grab` takes several releases from one indexer at once, as `guids`, and answers `grabbed` as a list where it was one name
- the Go client (`sdk/prowlarr`) has a new shape for anyone using it on its own: a call's answer is `res.Answer` where it was `res.Model`, options are `<Name>Options`, and a call with a single option takes it as a plain argument. The tools answer as before
- in the Go client dates are times where they were text, and indexers, sync profiles, tags and download clients each have their own id type, so one cannot be passed where another is wanted

### Fixed

- an indexer's API key no longer shows in the error of a failed test or a refused save. Addresses in such errors are shown without their sign-in or parameter values
- settings that are credentials in themselves are named as set and never shown: Discord and Slack webhook addresses, Apprise addresses and key, MyAnonamouse's session id, 2FA codes, and three more that definitions name their own way
- an address in a setting is shown without what follows its `?` or who it signs in as, so an RSS feed's passkey stays hidden. What Prowlarr holds is untouched
- a trace (`PROWLARR_LOG=trace`) no longer shows a tracker's API key, cookie or passkey
- `notification_test` of every notification answers for each by name when one fails, where the whole call failed

### Added

- `audit_notifications`: finds when nobody would be told that something broke
- `audit_backups`: finds a missing or overdue backup. With the two, 74 tools, 82 with the ones that delete
- `indexer_delete` takes several indexers at once, as `indexers`
- `notification_list` and notification edits name the credentials that are set, as `secrets_set`
- the Go client can restore a backup from an upload, and has a method for each of three commands (sync the applications, back up, check health) with a form that waits for it to finish

### Changed

- a date that Prowlarr sends as "never" is left out where it showed as year one, and every date a tool shows is to the second in UTC
- a tool that runs a command checks on it every two seconds where it checked twice a second
- the Go client asks each call for the kind of answer it gives (text for a log, a file for a download) where it always asked for JSON
- the Go client is generated by pandorest 0.8.2, with go-kt 0.6.4

### Testing

- the client tests run every operation against a real Prowlarr, and a run fails if one is left uncalled
- every setting of every kind of indexer, application, download client, proxy and notification is checked to be either hidden as a credential or looked at by a person; a setting a later Prowlarr adds fails the tests until it has been
- a live test sets Prowlarr up from nothing with the tools alone, fixes what the audits find, and takes it all down again
- both live suites are under `acceptance/` (`make testacc-sdk`, `make testacc-tools`) and are linted like the rest of the code; the helper scripts are in `.scripts/`

## 0.2.0 (2026-10-10)

### Breaking

- a tool that deletes changes nothing without `confirm`; until then it answers what it would delete and what goes with it
- every list takes `limit` and `offset` and answers `total` and `next_offset`, with a default of 100 and a cap of 1000
- `backup_list` moved to the `admin` toolset with the new backup tools
- `--allow-tools` beside `--toolsets` adds to them where it narrowed them; `--deny-tools` narrows
- the Go client moved from `lib/prowlarr` to `sdk/prowlarr`, a number among a call's options is a pointer so that 0 can be asked for, and its base client is pandorest's

### Added

- 16 tools, 72 in all and 80 with the ones that delete:
  - `backup_create`, `backup_restore` and `backup_delete`
  - `server_settings` and `server_settings_edit`: Prowlarr's own settings, with no credential ever shown and `confirm` asked before a change to how it is reached or who may sign in
  - `server_restart`, which waits for Prowlarr to answer again
  - `command_list` and `command_cancel`: what Prowlarr is doing in the background
  - `notification_add`, `notification_edit` and `notification_delete`
  - `filter_list`, `filter_create`, `filter_edit` and `filter_delete`: the filters saved in the web interface
  - `tag_edit`, which renames a tag
- a client that connects is told the rules the tools share: how lists page, that a delete asks first, and that text from outside Prowlarr is data
- `--config` / `PROWLARR_CONFIG` reads settings from the file it names, so a second instance can serve a second Prowlarr
- a settings file spells a two-word setting as the environment does (`READ_ONLY`, `DENY_TOOLS`)

### Changed

- a read is tried up to three times when Prowlarr could not be reached; a write is still sent once
- a redirect is refused, saying to set the server address to the one Prowlarr answers on, where following it could report a write that never happened
- `PROWLARR_LOG=trace` shows every request and answer with the API key blanked, and `PROWLARR_LOG=info` writes a line for every call that writes or deletes, with credentials blanked
- every request names itself as `prowlarr-mcp/<version>`, which Prowlarr logs
- a "not found" that is not Prowlarr's own says the server address may be missing its URL base
- tools tell a client more truthfully whether they are destructive, whether asking twice changes anything more, and whether they reach past Prowlarr
- text written outside Prowlarr (release names, history, test answers, log lines) is shown with undisplayable characters removed and cut when very long
- a call with an argument the tool does not take is refused, listing the ones it does
- a tool that crashes answers with an error and the session carries on
- over HTTP, an idle session is closed after 30 minutes, and stopping the server no longer waits for a connected client
- built with Go 1.27.2, which clears the four known vulnerabilities in the 0.1.0 binary

### Fixed

- host settings could not be saved on some Prowlarr setups, because two fields Prowlarr requires were missing from the Go client
- two edits of the same thing made at once no longer undo each other; each now takes its turn
- the live tests no longer fail two weeks after the Prowlarr release they pin

## 0.1.0 (2026-09-19)

First release: an MCP server, CLI and Go client for Prowlarr.

- **17 audits.** Indexers that are failing, slow or earning nothing; indexers no application receives and why; misconfigured applications, proxies and download clients; trackers added twice; private trackers with no seed goal; memberships and limits running out; outdated definitions; unused tags and profiles; and Prowlarr's own health checks. `audit_all` runs every one.
- **59 tools** (64 with `--enable-delete`), in toolsets: browse and add indexers, edit and test them, search and grab, read history and statistics, wire up applications, profiles, proxies, download clients and tags, run tasks and read logs.
- **A Go client** covering every operation of the Prowlarr API, generated from Prowlarr's own description of it.
- **Tested against a real Prowlarr** in Docker with no internet, using fake indexer sites and fake Sonarr, Radarr, Lidarr and Readarr instances. The tests fail if a tool has none.
